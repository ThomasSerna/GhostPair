## What changed in 0.6.6

- **Single-page application navigation:** Kept the shared view, presentation metadata and remote control active when a shared tab changes URL through `history.pushState` or `history.replaceState` without changing its top-level document.
- **Clipboard synchronization lifecycle:** Published pre-connection remote clipboard state before starting the initial clipboard poll, propagated automatic clipboard error disablement across host snapshots and the guest offscreen adapter, and recreated the offscreen clipboard document if Chrome closed it while idle.
- **Viewer and session reliability:** Preserved the active shared `<video>` stream when toggling remote control or when presentation metadata arrives after the first decoded frame, and cleaned up pending viewer requests if the connection page reconnects on the same tab.
- **Extension code cleanup:** Removed unused offscreen markup, redundant viewer state checks, duplicate/unused CSS rules and leftover untranslated clipboard error messages.

## Compatibility and limits

- Existing connection codes for `https://ghostpair-3c9f3903aad3.herokuapp.com`, saved connection settings, preview preferences, Manifest V3 permissions and peer protocol `4` are unchanged. Reload both unpacked extensions after updating.
- Direct WebRTC without TURN, explicit per-tab host authorization, visible browser capture indicators and `Event.isTrusted` limitations on protected pages remain unchanged.
